One page per function. Each answers one question, and refuses by name when it can't.

Tier 1: one color, or one pair. P3 is first-class and sRGB is the fallback; every gamut-aware tool asks for the gamut and has no default.

  • parseColor — What did I type?
  • maxChroma — How vivid can this step be?
  • inGamut — Is this displayable on this screen?
  • gamutMap — Where does it land if not?
  • deltaEOK — How far is this step from its neighbour?
  • contrastWCAG / contrastAPCA — What does this pairing measure?
  • checkContrast — Does this pairing clear?
  • solveBackground — How far can the surface move before it stops clearing?
  • solveForeground — What's the nearest ink that clears on this surface?
  • rotateHue — What's this color at another hue?
  • harmony — Which hues are in harmony with this one?
  • formatOklch — What does the stylesheet get?
  • formatHex — What does a hex-only consumer get?

Tier 2: a list of steps. Built from Tier 1 only; an architectural test enforces it.

  • inspectRamp — What does each step I placed measure, and how do the neighbours relate?
  • minPass — Which is the first step that clears on this surface?
  • createScale — Equal steps in data → equal perceived steps?
  • createRamp — A ramp to start from.

Tier 3: a whole system. The opinion layer; every part rebuildable from Tiers 1–2.

  • resolveBinding — Bind one token: pick a step by eye, or solve for the first that clears.
  • buildTokenSet — Bind these ramps to these semantic roles, with a receipt per pairing.
  • tokenSetToDeclarations — What does this ship as, in plain CSS?
  • tokenSetToDesignTokens — What does this ship as, for a token pipeline?
  • tokenSetToTailwindTheme — What does this ship as, for Tailwind v4?
  • shadcn — A brand color in, shadcn's theme out: shadcnBindings, auditTokenSet, tokenSetToShadcnCss, tokenSetToRegistryItem.
